## 🧠 我怎么做技术选型

写代码的时间只占三分之一，剩下三分之二在维护。所以我的默认倾向是：

- **能用的现成方案，绝不自己造。**&#8203; 自研的前提是现成的真的不够用。
- **先跑通，再优化。**&#8203; 过早优化是给未来的自己挖坑。
- **抽象等到第三次重复再抽。**&#8203; 两次是巧合，三次才是模式。
- **类型和日志比注释可靠。**&#8203; 注释会说谎，编译器不会。
- **删代码比加代码更需要勇气。**&#8203; 没被删过的项目，通常也没被认真维护过。
